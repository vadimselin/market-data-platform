# CLAUDE.md

## Что это за проект

`market-data-platform` — учебный пет-проект дата-инженерного пайплайна.
Забор OHLCV-свечей с публичного API Binance → raw-слой в Parquet → загрузка
в аналитическую БД → витрины → оркестрация Airflow → мониторинг Prometheus/Grafana.

Проект одновременно является **учебным полигоном** по плану на 26 недель.
Цель — переход из аналитика данных в дата-инженеры внутри компании (TradingView).
Ориентир по стеку — вакансия TradingView Data Engineer: Python, Airflow, dbt,
SQL-оптимизация, AWS, MPP-базы (Redshift), Docker, Prometheus/Grafana.

## Стиль объяснений

Я аналитик данных с 4 годами опыта. Сильные стороны: SQL (PostgreSQL),
Python на уровне pandas и алгоритмических задач. **Слабые: DevOps, Linux,
системные концепции — опыта нет вообще.**

- **Поясняй каждый незнакомый термин при первом появлении**, прямо в скобках.
  Не «`ps` читает `/proc`», а «`ps` читает `/proc` (специальная папка,
  где ядро показывает информацию о процессах в виде файлов)»
- **Флаги — с расшифровкой по полному имени**, не «флаг -e», а
  «`-e` = errexit, выйти при первой ошибке»
- **Один концепт за раз.** Не вываливай побочные факты там, где я решаю
  другую задачу. Сначала основное, побочное — по запросу
- **Аналогии из SQL работают лучше всего.** Пакет = схема, конвейер = курсор,
  уровни логов = `WHERE severity >= N`, `uniq` требует `sort` как `GROUP BY`
- **Команды в правильном порядке выполнения.** Проверяй зависимости между шагами
- Не предполагай знания Linux. Явное лучше неявного

## Технический стек и соглашения

**Окружение:** macOS на Apple Silicon, zsh + oh-my-zsh, OrbStack вместо
Docker Desktop, nvim как редактор.

**Пакеты:** `uv`, Python 3.12 (пин в `.python-version`).
`pip install` не используется — только `uv add`.
`uv.lock` коммитится обязательно.

**Структура:** src-layout, пакет установлен в editable-режиме.
Подпакеты по назначению: `config/`, `loaders/`, `storage/`.

**Конфигурация:** `pydantic-settings`, класс `Settings` в
`config/settings.py`. Приоритет: переменные окружения → `.env` → дефолт.

**Логирование:** `logging`, `logger = logging.getLogger(__name__)` в начале
каждого модуля, `setup_logging()` один раз в точке входа.
`print` в коде не используется. Формат `logger.info("текст %s", value)`,
не f-строка.

**Инфраструктура:** `docker-compose.yml`, имя проекта `market-data`,
Postgres 17 на порту 5433 снаружи, named volume `pgdata`, healthcheck.

**Коммиты:** Conventional Commits — `feat:`, `fix:`, `docs:`, `chore:`,
`refactor:`, `test:`, `perf:`. Сообщения на русском.
