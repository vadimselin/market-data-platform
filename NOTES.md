**Застрял на:** `uv python pin 3.12` упал с ошибкой — сначала надо было
поправить `requires-python` в `pyproject.toml`, потом пинить.

**Ответ на вопрос:** контейнер несёт своё пользовательское пространство
(файловую систему со своей версией Python), но использует ядро извне.
Изоляция — namespaces (видимость) и cgroups (ресурсы), обе функции ядра Linux.
На macOS ядро берётся не у мака (там Darwin), а у лёгкой Linux-VM,
которую поднимает OrbStack. Цепочка: macOS → VM → контейнеры.

Проверено:
```bash
  uname -r на хосте        → 25.5.0 (Darwin)
  в python:3.12-slim       → 7.0.11-orbstack-...
  в alpine                 → 7.0.11-orbstack-...   (то же самое!)
  /etc/os-release          → Debian 13 vs Alpine 3.24 (разные)
```
**Открытые хвосты:**
- `docker run python:3.12-slim` — сравнить `uname -a` внутри и снаружи
- разобраться, чем `uv.lock` отличается от `pyproject.toml` по уровню точности

## Спринт 0.2 — 2026-08-02

**Вопрос:** Почему `grep` в связке через `|` работает быстрее и на файлах любого размера, а pandas на большом CSV падает с нехваткой памяти?

Потому что `pandas` загружает весь файл в RAM а grep в связке с "трубой" `|` работает через буфер в 64кб. То есть при запуске условно `grep X file.txt | wc -l` grep выбирает строки X, пока те влезают в 64кб, а потом передет их на подсчет в утилиту wc

**Сделал:**
- Полигон: 5 CSV по 2000 строк (~/projects/bash-lab)
- Просмотр без открытия: `head`, `tail`, `wc -l`
- Конвейеры: `cat | grep | wc -l`, сравнение с `grep -c`
- Колонки через `awk -F',' '{print $2}'`, агрегация `sort | uniq -c`
  — это буквально GROUP BY
- Перенаправление: `>`, `>>`, `2>`, `2>&1`, `/dev/null`
- Коды возврата `$?`, цепочки `&&` и `||`
- Разобрался с алиасами (oh-my-zsh), многострочным вводом

**Застрял на:** `time(...)` без пробела → zsh ругается про glob qualifier.
`time` — отдельное слово, пробел обязателен.

**Ошибся:** думал, `grep -c` считает совпадения. Он считает СТРОКИ,
в которых есть совпадение. `echo "BTC BTC" | grep -c BTC` → 1.
Совпадения считает `grep -o BTC | wc -l` → 2.

**Ответ на вопрос:** pandas загружает файл в RAM целиком, потому что
строит таблицу с произвольным доступом (сортировка, join, обращение
к любой строке). Конвейер работает потоково: труба между процессами —
буфер 64 КБ, в памяти в каждый момент только он. Когда буфер полон,
ядро приостанавливает писателя, пока читатель не разгребёт (backpressure).
`wc` не хранит строки — только счётчик, поэтому размер файла не важен.

Замеры:
  cat *.csv | grep BTCUSD | wc -l   → 0.011s, 144% CPU (3 процесса параллельно)
  grep -c BTCUSD *.csv              → 0.007s,  78% CPU

  Связать с блокирующими операциями в плане SQL-запроса (Фаза 4)

- почему `uv run` работает без активации venv
- чем `uv.lock` отличается от `pyproject.toml` по точности
- перенести NOTES.md внутрь репозитория
